# Attention到底在干嘛？为什么它是Transformer的核心

上一篇[《Encoder-only、Decoder-only、Encoder-Decoder三种架构详解与对比》](./transformer_base_encoder_decoder.md)讲了Transformer的三种架构，提到它们的共同基础是"自注意力机制"。

但到了真实项目和面试里，还有一个问题绕不开：**Attention到底在做什么？为什么它是Transformer的核心？** 不理解这一层，后面的多头注意力、位置编码、KV Cache都会觉得抽象。

面试官常这么问："说说Attention机制，Q、K、V分别是什么？"

## 常见错误回答

"Attention就是注意力机制，Q是查询，K是键，V是值，通过计算相似度来加权求和。"

**这个回答方向没错，但没讲到工程本质。** 面试官听完会接着追问：为什么要拆成三个矩阵？为什么不能用全连接层？Attention解决了什么RNN解决不了的问题？

这三个追问答不上来，说明你只记住了名词，没理解机制。**Attention的核心不是"注意力"三个字，而是让每个Token能根据上下文动态决定关注谁，而不是固定权重。**

## 简要回答

Attention机制让每个Token能"看到"上下文的所有Token，并根据相关性动态调整关注程度。它通过Q、K、V三个角色完成这件事：

- **Query（Q）**：当前Token在问"我该关注谁？"
- **Key（K）**：其他Token在回答"我有没有你需要的信息？"
- **Value（V）**：真正被提取和聚合的语义信息

**核心流程**：Query和Key做点积算出相似度分数 → Softmax归一化成权重 → 用这些权重对Value加权求和 → 得到融合了上下文信息的新表示。

**Attention和全连接的本质区别**：全连接的权重是训练好的固定参数，所有输入用同一套权重；Attention的权重是根据每次输入的上下文动态计算的，输入不同权重就不同。这就是为什么Attention能处理变长序列、捕捉长距离依赖，而全连接做不到。

## 详细回答

### Attention在做一件很像人类的事

先看这句话：

> 小明打了小刚，因为他生气了。

这里的"他"指的是谁？小明还是小刚？

你不会随机回答，你会"先看一眼上下文"——"打了"这个动作和"生气"更可能对应发起方，所以"他"指小明。

**这就是Attention的直觉：从上下文中挑出和当前词最相关的部分，每个Token都会关注其他Token，但关注程度不一样。**

再看一个更长的例子：

> Transformer这个架构我学了一个月，中间去图书馆借了好几本书，现在终于明白它为什么强大。

"它"指的是什么？图书馆？好几本书？还是Transformer？

"Transformer"在句首，"它"在句尾，中间隔了一大串词。**RNN只能一步步往后传，信息每传一步就被稀释一次**，传到"它"的时候，句首的信息已经所剩无几。

Attention换了个思路：**"它"不等信息传过来，直接和每个位置算相关度。** 句首和句尾之间只隔一步，距离再远也不衰减。

### 为什么要拆成Query、Key、Value三个角色？

很多人第一次看到QKV会懵：为什么不直接算相似度，非要拆成三个矩阵？

**因为"问"和"答"的角色不对称。**

举个现实例子：你在知识库里搜索"Transformer原理"（这是Query），知识库里有很多文档，每篇文档的标题和标签是它的"索引信息"（这是Key），真正的内容是正文（这是Value）。

搜索时你用Query和Key匹配，找到最相关的几篇；然后你读的是Value（正文），而不是Key（标题）。

**回到Attention：**

- **Query（Q）**：当前Token在问"我需要什么信息？"
- **Key（K）**：其他Token在说"我这里有什么信息？"
- **Value（V）**：其他Token携带的真正语义内容

**用"Query和Key匹配"决定关注谁，用"Value加权求和"提取真正的信息。** 这两件事分工明确，所以需要三个不同的矩阵。

### Query、Key、Value在实际句子中怎么工作？

看这句话：

> 远方走来一位身穿白裙、面带微笑的少女。

假设我们要计算"女"这个Token的新表示。

**第一步：Query发问。** "女"拿出自己的Query，问所有Token："谁能帮我说清楚我是什么样的？"

**第二步：Q·K打分。** "女"的Query和每个Token的Key做点积。"身穿白裙""面带微笑""少"这些修饰词和"女"关系紧，分数高；"的""远方"这类词分数低。

**第三步：Softmax变权重。** 把分数转成加起来等于1的权重。分数差距会被放大，"少"拿到0.32，"的"只剩0.01。

**第四步：按权重搬Value。** 用权重对每个Token的Value加权求和。权重大的Value搬进来的多，权重小的几乎不进来。

![Q、K、V分工计算示意](https://file1.kamacoder.com/i/web/20261021111231.png?v=20261005)

最后"女"的新表示不再是一个孤立的字，而是带上了"白裙、微笑、年轻"这些特征。

### Attention和全连接层的本质区别是什么？

全连接层也能融合信息，为什么不用全连接，非要用Attention？

**核心区别：权重是固定的还是动态的。**

拿"苹果"举例，放进两句话：

- 我吃了一个苹果
- 苹果发布了新手机

**全连接层**对每个词算W·x，W训练完就固定。两句话里的"苹果"输入一样，乘的是同一个W，输出也一样，模型分不出这是水果还是公司。

**Attention**的权重由Q·K按当前句子现算。第一句里"苹果"主要关注"吃了"，表示偏向水果；第二句里主要关注"手机"和"发布了"，表示偏向科技公司。

![全连接与Attention权重对比](https://file1.kamacoder.com/i/web/20261021111234.png?v=20261005)

左边灰色的词不参与"苹果"的计算，句子变了输出不变。右边绿色是"苹果"重点关注的词，换一句话，绿色的位置就换了，同一个词得到不同的表示。

注意别说过头：Attention里的W_Q、W_K、W_V训练完也是固定的。**动态的是注意力权重，它由当前句子的Q·K算出来。** 这才是Attention能理解指代、多义词和长距离依赖的原因。

### Embedding为什么是Attention计算的前提？

Attention不是直接操作文本，而是操作Embedding向量。

**Embedding的作用是把离散的Token（比如"你""我""爱"）映射成连续的向量空间，让"语义相近的词在空间中距离近"。** 比如"国王"和"王后"的Embedding在空间中很接近，"国王"和"苹果"的Embedding距离就远。

有了Embedding，Query和Key的点积才能衡量语义相关性。如果没有Embedding，Token只是编号（比如"你"=101，"我"=102），点积算出来的分数毫无意义。

**所以Transformer的第一步永远是Embedding，把Token变成向量，才能进入Attention计算。**

## 知识拓展

**Q1: Attention为什么要用点积算相似度，不能用其他方法吗？**

可以用其他方法（比如拼接后过全连接层），但点积是最高效的。点积的几何意义是"两个向量的相似度"，向量越接近，点积越大；向量正交，点积为零。这正好符合"相关性"的语义。而且点积可以并行化计算，速度快。Transformer选点积是效率和效果的平衡。

**Q2: Softmax为什么是必须的，不能直接用点积分数吗？**

点积分数没有归一化，不同句子、不同位置的分数量级差异很大，没法直接当权重用。Softmax把分数转成概率分布（所有权重加起来等于1），这样才能做加权求和。而且Softmax有平滑作用，能抑制过大的分数，防止某个Token独占注意力。

**Q3: 为什么叫"自注意力"（Self-Attention）？**

因为Query、Key、Value都来自同一个输入序列。每个Token既是"问问题的"（Query），也是"被关注的"（Key和Value）。"自己关注自己"，所以叫Self-Attention。和它对应的是Cross-Attention（交叉注意力），比如翻译任务里，译文的Query去关注原文的Key和Value，那就不是"自己"了。

**Q4: 面试怎么讲清楚Attention？**

先说Attention解决了什么问题：让每个Token能根据上下文动态调整关注程度，而不是固定权重。

再说QKV的角色：Query问"我该关注谁"，Key答"我有没有你需要的"，Value提供真正的信息。

最后说计算流程：Query和Key点积算相似度 → Softmax归一化成权重 → 用权重对Value加权求和 → 得到融合上下文的新表示。

能讲清这三层，面试官就知道你真懂了，不是背的。

**Q5: Attention的计算复杂度有什么问题？**

Attention的复杂度是$O(n^2)$，n是序列长度。因为每个Token都要和所有其他Token算相似度。序列长了，计算量和显存占用都会暴涨。这也是为什么后来有了稀疏注意力、线性注意力、Flash Attention这些优化方法。但核心思想不变，都是在Attention的框架下做工程优化。
