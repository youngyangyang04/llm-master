# 位置编码详解:Transformer为什么必须知道Token顺序,正弦编码原理

上一篇[《Multi-Head Attention详解:为什么一个头不够,多头怎么拆分和拼接》](./mha.md)讲了多头注意力的运作方式——多个头并行、各自关注不同关系,最后融合输出。

但有一个反直觉的事实:Attention 机制本身**完全不知道词的顺序**。把"我爱你"和"你爱我"这两句话输入进去,Attention 算出来的权重矩阵是一样的,因为它只看"有哪些词",不看"这些词在哪里"。

面试官一定会问:**Transformer 是怎么知道词的顺序的?位置编码是什么?为什么用正弦和余弦函数?可学习的位置编码和固定的位置编码有什么区别?**

这些问题的答案,就是 Positional Encoding(位置编码)的设计精髓。

## 面试官最爱问的一个追问

"Transformer 怎么知道词的顺序?"

很多录友会答:

> Transformer 用位置编码来表示词的位置。

面试官接着问:"位置编码怎么加进去的?为什么用正弦函数?可学习的位置编码和固定的位置编码哪个更好?"

答不上来。

问题出在哪?**你只知道"有位置编码",但没搞清楚为什么需要它、它是怎么工作的、不同设计的权衡是什么。** 面试官追问的都是设计动机——Self-Attention 为什么不感知顺序?位置编码怎么"补"回来?正弦函数的优势在哪?这些问题的答案藏在 Transformer 的结构里。

## 先做一个实验

看下面这两句话:

> 我打了他

> 他打了我

意思完全相反,但用的是**完全一样的词**,唯一的区别是**顺序不同**。

一个好的语言模型,必须能区分这两句话。那 Transformer 的 Self-Attention 能吗?

**不能。**

## Self-Attention 天然不感知顺序

这是 Transformer 一个反直觉的地方。

回忆一下 Self-Attention 的计算:每个 Token 和**所有其他 Token** 做内积,算出注意力权重,再加权求和。

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

在这个过程里,**Token 的位置信息从来没有参与过计算**。"我"在第一位还是第三位,对 QK^T 的结果没有任何影响。

用一句话来说:

**Self-Attention 眼里只有"有哪些词",没有"这些词在哪里"。**

你把输入序列的词顺序随机打乱,Self-Attention 算出来的注意力权重**完全一样**。

这就意味着,如果什么都不做,"我打了他"和"他打了我"在 Transformer 看来是**同一句话**。

## 为什么 RNN 不需要担心这个问题?

你可能会想:RNN 不也是处理序列的吗,它有这个问题吗?

没有。RNN 是**一个词一个词按顺序处理**的,天然把位置信息编进了隐藏状态里。第一个词处理完,才轮到第二个词,顺序是硬编码在结构里的。

而 Transformer 的优势之一,恰恰是**可以并行处理所有词**——所有 Token 同时进入 Self-Attention。但代价就是:**顺序信息丢了**,需要手动补回来。

**这是一个工程权衡:并行带来了训练速度,但牺牲了天然的顺序感知,必须用位置编码补回来。**

## 解决方案:位置编码

解决思路很简单:既然 Self-Attention 本身不感知位置,那就**在输入进 Attention 之前,把位置信息加进去**。

具体做法是:给每个 Token 的 Embedding 向量,加上一个代表它位置的向量,这个向量就叫 **Positional Encoding(位置编码)**。

$$
\text{输入} = \text{Token Embedding} + \text{Positional Encoding}
$$

加完之后,每个 Token 的向量里就同时包含了**语义信息**(它是什么词)和**位置信息**(它在第几位)。

**核心逻辑:Attention 看不到位置,就在进 Attention 之前把位置"写"进向量里。**

## 位置编码长什么样?

原始 Transformer 论文用的是**正弦和余弦函数**来生成位置编码,公式如下:

$$
PE_{(pos,\ 2i)} = \sin\left(\frac{pos}{10000^{2i/d}}\right)
$$

$$
PE_{(pos,\ 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d}}\right)
$$

我们一步步来看这两个公式。

**pos** 是位置(第几个 Token),**i** 是维度索引(第几维),**d** 是 Embedding 维度(比如 512)。

### 1. 为什么用三角函数?

位置编码需要满足几个条件:

1. **每个位置的编码唯一**,不能有两个位置一模一样
2. **位置之间的"距离"有规律**,相邻位置的编码应该相似,距离越远越不同
3. **可以泛化到更长的序列**,训练时没见过的位置也能用

正弦和余弦函数天然满足这几点:不同频率的波形叠加,就像一把"尺子",每个刻度的花纹都不一样,但整体有规律。

### 2. 为什么不同维度用不同频率?

位置编码是一个和 Token Embedding 等长的向量,比如 512 维。

正弦编码的聪明之处在于:**不同维度使用不同频率的波**。

- **低维度**:频率高,变化快 → 区分近距离的位置(第1个词 vs 第2个词)
- **高维度**:频率低,变化慢 → 区分远距离的位置(第1个词 vs 第100个词)

就好像用"秒"刻度区分相邻时刻,用"小时"刻度区分跨度更大的时间段——**不同精度的尺子,量不同尺度的距离**。

### 3. 为什么分数是 2i/d?

分母 10000^(2i/d) 控制频率。i 从 0 到 d/2,分母从 1 逐渐增大到 10000,频率从高到低。

这样设计的好处是:低维度(i 小)频率高,能区分相邻位置;高维度(i 大)频率低,能区分远距离位置。**一个位置编码向量的 512 维,就像 256 把不同精度的尺子,共同唯一标识这个位置。**

### 4. 为什么偶数维用 sin,奇数维用 cos?

sin 和 cos 是正交的,这样可以保证位置编码的不同维度之间尽可能独立,不会互相干扰。同时,sin 和 cos 的组合可以用三角恒等式表示位置之间的相对关系,这对模型学习相对位置很有帮助。

## 位置编码是固定的,还是学出来的?

原始 Transformer 论文用的是**固定的正弦编码**,不参与训练,直接按公式算好。

但后来很多模型(比如 BERT)用的是**可学习的位置编码**——位置编码也是一组参数,和词向量一起随训练更新。

两种方式在实践中效果相差不大,但各有侧重:

| | 正弦编码(固定) | 可学习编码 |
|---|---|---|
| **参数量** | 无额外参数 | 多一组位置参数(max_len × d_model) |
| **长序列泛化** | 理论上可以外推到更长序列 | 受训练长度限制,超过 max_len 需要插值或截断 |
| **训练成本** | 无需学习,直接用 | 需要学习,但通常收敛很快 |
| **代表模型** | 原始 Transformer | BERT、GPT-2 |
| **适用场景** | 序列长度不固定、需要外推 | 序列长度固定、训练数据充足 |

**工程权衡:固定编码省参数、能外推,但不一定最适合当前任务;可学习编码能针对任务优化,但不能外推到训练时没见过的长度。**

## 现代大模型用的是什么位置编码?

原始的正弦位置编码和可学习位置编码都是**绝对位置编码**——每个位置有一个固定的编码,和其他位置无关。

但现代大模型(比如 Llama、Qwen)基本都改用了 **RoPE(Rotary Position Embedding,旋转位置编码)**,这是一种**相对位置编码**:

- 不是给每个位置一个固定的向量,而是在计算 Attention 时,根据两个 Token 之间的**相对距离**来调整它们的相似度
- 用旋转矩阵编码位置,天然支持长序列外推
- 不增加额外参数,计算效率高

RoPE 的细节我们后续文章会专门讲,这里只需要知道:**RoPE 是相对位置编码,比绝对位置编码更适合长上下文场景。**

## 面试怎么回答

面试官问"Transformer 怎么知道词的顺序",你可以这样答:

**第一层:为什么需要位置编码**

"Self-Attention 的计算只依赖 Token 的内容,不依赖位置。把'我爱你'和'你爱我'输入进去,Attention 算出来的权重是一样的,因为它只看'有哪些词',不看'这些词在哪里'。所以必须在进 Attention 之前,把位置信息加进 Token Embedding 里,这就是位置编码的作用。"

**第二层:怎么做位置编码**

"原始 Transformer 用的是正弦余弦函数生成位置编码,不同维度用不同频率,低维度频率高、能区分相邻位置,高维度频率低、能区分远距离位置。这样一个 512 维的位置编码向量,就像 256 把不同精度的尺子,共同唯一标识这个位置。正弦编码是固定的,不参与训练,好处是可以外推到更长的序列。"

**第三层:工程权衡**

"正弦编码和可学习编码各有优劣。正弦编码不增加参数、能外推,但不一定最适合当前任务;可学习编码能针对任务优化,但不能外推到训练时没见过的长度。现代大模型基本都用 RoPE 这种相对位置编码,不增加参数、支持长序列外推,效果比绝对位置编码更好。"

**能说到第三层,面试官会觉得你不仅懂原理,还懂不同方案的权衡。**

## 知识拓展

### 1. 位置编码为什么是"加"到 Token Embedding 上,而不是"拼接"?

拼接会增加维度,比如 Token Embedding 是 512 维,位置编码也是 512 维,拼接之后就是 1024 维,参数量和计算量都会翻倍。加法不改变维度,更高效。

而且,加法隐含了一个假设:语义信息和位置信息是独立的、可以线性叠加的。实践中这个假设基本成立。

### 2. 位置编码会不会"覆盖"Token Embedding 的语义信息?

不会。位置编码的数值范围在 [-1, 1] 之间,Token Embedding 的数值范围通常也在这个量级。两者相加之后,语义信息和位置信息都保留了下来,只是混合在同一个向量里。

Attention 机制会自动学习如何从这个混合向量里提取有用的信息。

### 3. 正弦位置编码能外推到无限长的序列吗?

理论上可以,因为正弦函数是连续的,任何位置都能算出一个编码。但实际上,模型在训练时只见过有限长度的序列(比如 512),外推到更长序列时效果会下降,因为模型没学过怎么处理那些位置。

RoPE 的设计天然支持长序列外推,效果比正弦编码好。

### 4. 为什么 BERT 用可学习位置编码,GPT 用正弦编码?

这主要是历史选择。BERT 的序列长度是固定的(max_len = 512),训练数据充足,用可学习编码能针对任务优化。GPT 的序列长度不固定,用正弦编码能外推到更长序列。

但后来发现,可学习编码和正弦编码效果差不多,现在大部分模型都改用 RoPE 了。

### 5. 位置编码只在输入层加一次,后面的层怎么知道位置?

位置信息加到 Token Embedding 之后,会通过 Attention 和 FFN 传递到后续的层。每一层的 Attention 计算都会用到前一层的输出,位置信息就隐式地保留在了每一层的表示里。

不需要每一层都加一次位置编码,只在输入层加一次就够了。

## 本文小结

Transformer 用 Self-Attention 并行处理所有词,带来了速度优势,但也丢掉了顺序信息。位置编码就是用来"补"回这个信息的——在输入进 Attention 之前,把每个 Token 的位置"写"进它的向量里。

正弦位置编码的设计看起来复杂,本质上是一把多精度的尺子:不同维度、不同频率,共同唯一标识每个位置,还能泛化到更长的序列。

**面试官追问的都是设计动机**:为什么 Self-Attention 不感知顺序?位置编码怎么"补"回来?正弦编码和可学习编码的权衡是什么?这些问题的答案不在公式里,在 Transformer 的结构特点和工程权衡里。

把每一步的设计目的、不同方案的优劣讲清楚,面试官才会觉得你真的懂位置编码,而不是背概念。
