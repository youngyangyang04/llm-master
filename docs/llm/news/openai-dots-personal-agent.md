# OpenAI Dots发布：ChatGPT不等你提问了，个人Agent开始24小时替你干活

> 国内充值ChatGPT会员，推荐看这里 [ChatGPT充值服务](../../ai/chatgpt/recharge.md)

前几天写 [GPT-6 Astra](./gpt-6-astra.md) 的时候，我说这代模型最值得注意的，不是跑分又涨了多少，而是它开始真正接管鼠标、浏览器和工作流。

现在 OpenAI 把这件事往前推了一大步。

2026年9月29日，OpenAI 在 DevDay 发布了 **Dots**。

![OpenAI DevDay发布Dots个人Agent](https://file1.kamacoder.com/i/web/20261004104720.png?v=20261005)

一句话解释：**Dot 是一个24小时在线、拥有自己电脑、能在你不说话时继续干活的个人 Agent。**

你可以给它起名字、选形象、接入邮箱和工作软件，然后把一件需要长期盯着的事情交给它。

它不是回答完一句就消失。

它会记住进度、判断下一步、等条件变化，再决定什么时候继续；遇到真需要你拍板的事情，才回来找你。

这才是 Dots 和普通 ChatGPT 最大的区别。

**以前你是在“使用 AI”，现在 OpenAI 想让你开始“带一个 AI 同事”。**

## 一、别把它理解成换了头像的ChatGPT

普通 ChatGPT 的基本逻辑是：

你问一句，它答一句。你下一个任务，它再继续。

即使开启记忆、定时任务和工具调用，工作的中心仍然是这一轮对话。

Dot 的中心不是“对话”，而是**责任**。

比如你不只是让它“整理今天的用户反馈”，而是把“持续跟踪用户反馈，每周归类问题，发现高风险投诉立即叫我，普通变化更新到周报”这份责任交给它。

这两个任务看起来只差了几句话，底层完全不是一回事。

| 普通ChatGPT | Dot |
|---|---|
| 围绕一轮问题给答案 | 围绕一个长期目标持续推进 |
| 通常等用户再次发消息 | 可以自己暂停、唤醒和继续 |
| 结果主要留在当前对话 | 能跨会话、任务和沟通渠道保留上下文 |
| 一次处理一条主线 | 可以调度后台Agent并行推进 |
| 你负责盯进度 | 它负责跟进，只在需要判断时找你 |

所以如果一定要找一个大家熟悉的类比，它确实有点像**托管在 OpenAI 云端的 OpenClaw**。

但这个类比只适合帮助理解，不代表两者完全一样。

OpenClaw 更像一套可以自己部署、自己改造的个人 Agent 框架；Dots 则把模型、云电脑、记忆、权限、插件和消息入口全部塞进 ChatGPT 账户体系里。

前者自由度高，后者上手门槛低。

OpenAI 看上的显然不是少数极客，而是那些从来没部署过 Agent、也不想折腾环境的普通用户。

## 二、Dot凭什么能在你离开后继续干活

一个 Dot 背后，至少有五层能力。

**第一层，GPT-6 Astra。**

Dots 由 GPT-6 Astra 驱动。它负责理解目标、拆解任务、判断什么时候继续、什么时候暂停，以及哪些决定必须交还给人。

**第二层，独立的云电脑和浏览器。**

每个 Dot 都有自己的云端电脑、文件、软件和浏览器会话。即使你的笔记本已经合盖，它仍然能继续研究资料、分析数据、准备文档或者处理代码。

你随时可以打开它的电脑查看现场；需要亲自登录或处理敏感步骤时，也能点 `Take over` 接管鼠标和键盘，做完再把控制权还回去。

**第三层，持续记忆。**

它会结合当前对话、相关的 ChatGPT Memory，以及自己保存的偏好、决定和工作笔记来推进任务。

也就是说，你上周告诉它“低于5000美元不用找我”，这周它处理同类事情时，不应该又从头问一遍。

**第四层，后台任务和并行Agent。**

Dot 可以把工作拆给多个后台 Agent，同时继续和你沟通。比如一条线查供应商报价，一条线核对日历，一条线整理风险，最后由 Dot 收结果、找冲突、给你结论。

这和前面写过的 [Codex Record & Replay](./codex-record-replay.md) 正好接上：Skill 负责教 Agent 某件事怎么做，Dot 负责判断这件事什么时候该做、做完以后下一步是什么。

**第五层，插件和真实工作环境。**

![Dots可连接超过4000个ChatGPT应用](https://file1.kamacoder.com/i/web/20261004104721.png?v=20261005)

OpenAI 在发布会上给出的数字是：ChatGPT 生态已经有 **4,000+ 应用**可供 Dots 协作。

它可以通过 Gmail 找邮件、从 Google Drive 读取和更新文档、在 GitHub 调查问题并准备代码修改。每个插件仍然受账户权限约束，不是连上以后什么都能干。

你也可以额外授权自己的电脑。

这里要分清楚两台机器：

- **Dot 的云电脑**一直在线，适合网页、资料、文档和云端任务。
- **你的本地电脑**只在设备联网、ChatGPT 桌面端保持运行时可用，适合本地文件、内部工具和现有 Codex 任务。

这套结构真正解决的是 Agent 最难的一件事：**模型想得明白，还得有地方执行；能执行，还得拿得到正确权限。**

## 三、它开始主动找你，而不是等你打开聊天框

Dots 还有一个很容易被低估的变化：入口不再只有 ChatGPT。

同一个 Dot 可以出现在 ChatGPT、Slack、Microsoft Teams 和语音通话里。换一个入口不会新建一个 Agent，它的记忆也不会清零。

你可以规定：

- 日常进度留在 ChatGPT；
- 截止日期可能延期时去 Slack 找你；
- 真要做选择时，直接拉起语音沟通；
- 短信入口后续开放。

电话目前是**你主动打给 Dot**。Dot 主动给你打电话是后续能力，不要被“24小时在线”理解成半夜会突然来电。

这个设计比“又多了一个聊天入口”更重要。

过去是人想起一件事，再打开软件找 AI。Dots 想做的是反过来：**Agent 盯着事情，只有事情值得占用你的注意力时，它才来找人。**

真正稀缺的已经不是答案，而是人的注意力。

## 四、Dots和ChatGPT Space放在一起，才是完整产品

OpenAI 同场还发布了 ChatGPT Space。

![OpenAI发布ChatGPT Space协作空间](https://file1.kamacoder.com/i/web/20261004104726.png?v=20261005)

Space 把 Pages、文件、表格、演示文稿、图片和 Sites 放进一个共享工作空间。人可以直接编辑，也可以邀请同事查看、评论和协作。

最关键的是，你可以在 Page 里直接 `@dot`。

比如一张产品发布页里，Dot 可以：

- 汇总这周新出现的用户问题；
- 对照产品文档，找出已经过期的描述；
- 把一段数据更新成图表；
- 在评论里列出仍然需要人确认的决策；
- 根据新的测试结果改写结论。

![ChatGPT Space中的Living Pages动态页面](https://file1.kamacoder.com/i/web/20261004104727.png?v=20261005)

发布会把这种页面叫 **Living Pages**。

名字挺准。

传统文档写完以后就开始变旧。Living Page 的目标是让 Agent 持续读取新的上下文，把页面维护成一个会变化的工作现场。

但这里也别脑补过头。OpenAI 官方文档明确提醒：**在 Page 里写一句“每天更新”，并不等于真的建立了定时任务。** 需要持续执行的工作，仍然要单独创建 Schedule，并检查它是否启用、实际跑过没有。

所以 Dots 和 Space 的关系可以这样理解：

**Dot 是干活的人，Space 是人和Agent共同交付结果的桌面。**

一个负责持续推进，一个负责沉淀上下文、协作和验收。

## 五、企业不只想要一个Dot，而是想要一支Agent团队

![OpenAI展示财务营销法务等Specialist dots](https://file1.kamacoder.com/i/web/20261004104724.png?v=20261005)

个人用户先得到一个通用 Dot，企业端则预览了 **Specialist dots**。

翻译成人话，就是让公司按岗位配置 Agent：

- 财务 Dot 盯发票、预算和异常；
- 营销 Dot 看活动数据、素材和渠道反馈；
- 法务 Dot 做合同初筛和条款对照；
- 客服 Dot 整理工单并跟踪处理状态。

通用 Agent 最大的问题，是“什么都能聊，但不知道你们公司到底怎么干活”。

Specialist dots 想补的是组织上下文：共享公司目标、流程、权限边界和反馈标准，让 Agent 不只是能力强，还知道自己在这家公司应该怎么做事。

这个方向没问题，但落地难度也比个人 Dot 大得多。

个人助理做错一张行程表，最多让你多改几分钟；法务 Dot 漏掉一条关键条款、财务 Dot 发错一笔钱，损失完全不是一个级别。

**Agent 越接近业务闭环，评估、权限和审计就越不能省。**

## 六、谁能用，聊天真的不算额度吗

Dots 正在分批开放，不是账号符合条件就立刻出现。

![OpenAI Dots套餐开放与使用额度说明](https://file1.kamacoder.com/i/web/20261004104723.jpg?v=20261005)

按 OpenAI 当前官方文档：

| 套餐 | Dots开放情况 |
|---|---|
| Pro 100 / Pro 200 / Pro 500 | 面向18岁以上用户开放，暂不含欧洲经济区、英国和瑞士 |
| Business Premium | 全球逐步开放 |
| Enterprise | 全球逐步开放，但默认关闭，需要管理员启用 |

首个 Dot 包含在符合条件的套餐里，不额外收费。

**和 Dot 的普通对话，不占 ChatGPT 对话额度。**

但这句话千万别只看前半截。

Dot 创建或管理的 Work、Codex 任务，仍然会按对应产品规则消耗额度；更深度的工作也有单独 allowance。发布后第一个月会给更高额度，不代表以后永远无限用。

OpenAI 还预告了后续收费方式：可以按月增加更多 Dot，或者提升单个 Dot 的速度和每月工作量。

这套商业模式其实很像招人：先送你一个基础席位，想要更快、更多、分工更细，再加钱。

## 七、卡哥得泼盆冷水：常驻Agent的风险，比聊天机器人大得多

Dots 看着很顺，但录友别一上来就把邮箱、GitHub、电脑和公司资料全部打开。

它比普通 ChatGPT 多出来的每一种能力，也对应一种新风险。

**第一，记忆越长，错误也可能延续越久。**

一次对话理解错了，你改一句就完事。一个持续工作几周的 Agent 如果把错误偏好写进自己的工作笔记，后面的决策可能一直在错误轨道上。

**第二，能主动执行，就意味着错误会真的落地。**

它不是只给你一段建议，而是可能改文件、更新文档、准备代码、操作网站。OpenAI 也明确写了：停止任务不会撤销已经完成的操作。

**第三，跨渠道上下文很方便，也最容易造成信息串线。**

你在私人对话里说过的内容，不应该顺手出现在团队 Slack。Dots 会在向其他人分享私人内容前检查授权，但涉及客户、合同和内部数据时，不能只靠一句“系统会检查”。

**第四，本地电脑权限不要常年裸奔。**

不用时就撤销访问；只给任务需要的插件；邮箱能只读就别先开写入；发消息、付款、合并代码这类动作保留人工确认。

我的建议很简单：先给 Dot 一份**低风险、可检查、长期重复**的责任。

例如跟踪公开资料、维护选题库、整理反馈、准备周报草稿。跑两周，看看它会不会漏、会不会自作主张、什么时候打扰你，再逐步加权限。

别反过来。

权限一把梭，然后等第一次事故教你什么叫最小授权，学费会很贵。

## Dots真正改变的，不是聊天框

这几年 Agent 产品总在强调“我能替你点多少按钮”。

Dots 往前走了一步：它开始强调**我能不能替你守住一件事**。

点按钮是动作，守住目标才是责任。

如果这条路走通，未来我们给 AI 的指令不会再是“帮我写一份周报”，而会变成“从今天开始，这个项目的进度和风险你负责盯着”。

但现在，先别急着幻想一人公司。

挑一件小事，给它边界，给它权限，也给它验收标准。

能连续一个月不掉链子，再叫同事。
