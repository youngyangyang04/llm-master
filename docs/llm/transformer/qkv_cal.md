# Attention计算全过程:从QK转置到Softmax加权求和一步步拆解

上一篇[《Attention到底在干嘛?为什么它是Transformer的核心》](./qkv.md)讲了 Q、K、V 的直觉含义——Query 在问"我该注意谁",Key 在回答"注意我",Value 是真正的信息。

但到了面试里,面试官不会只让你讲直觉,一定会追问:**Attention 是怎么算出来的?QK^T 那一步为什么要转置?为什么要除以根号d?Softmax 之后得到的权重矩阵是什么维度?**

这些问题不是背公式就能答的,你得把每一步的目的、输入输出的维度、具体数值的计算过程讲清楚。这篇文章我们就用一个最小的例子,把 Attention 的计算过程一步步拆开。

## 面试官最爱问的一个追问

"Attention 的公式你能推导一遍吗?"

很多录友会直接背公式:

> Attention(Q, K, V) = softmax(QK^T / √d_k) · V

面试官接着问:"为什么 K 要转置?不转置行不行?"

答不上来。

问题出在哪?**你只记住了公式长什么样,但没搞清楚每一步在干什么、为什么这么设计。** 面试官追问的都是工程直觉——为什么要除以根号d_k?这一步不做会怎样?这些问题的答案藏在计算过程里,不在公式里。

## Attention 计算的四个步骤

Attention 的完整计算过程分四步:

1. **计算 Q 和 K 的点积**:得到每对 Token 之间的相似度分数
2. **缩放**:除以 √d_k,防止分数过大导致梯度消失
3. **Softmax 归一化**:把分数变成概率权重,每行和为 1
4. **加权求和 Value**:用权重对 V 做加权平均,得到最终输出

**核心逻辑:先算相似度,再归一化成权重,最后用权重提取信息。**

整个流程用公式表达就是:

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

接下来我们用一个最小的例子,把每一步算一遍。

## 举一个最小的例子

假设输入序列是三个 Token:

> **我 爱 你**

每个 Token 经过 Embedding 之后变成一个 2 维向量(真实场景里通常是 512 或 1024 维,这里用 2 维方便手算):

| Token | 向量 |
|-------|------|
| 我    | [1, 0] |
| 爱    | [0, 1] |
| 你    | [1, 1] |

把三行拼在一起,就得到输入矩阵 X,形状是 3×2(3 个 Token,每个 2 维)。

为了简化计算,我们假设 W_Q = W_K = W_V = 单位矩阵,所以 **Q = K = V = X**。真实训练中这三个矩阵是不同的,是学习得来的,这里先理解流程。

## 第一步:计算 QK^T(谁和谁更相关?)

有了 Q 和 K,我们要计算**每对 Token 之间的相关程度**。

直觉是这样的:两个向量越"相似",它们的**内积**(点积)就越大。比如两个向量 [1, 0] 和 [1, 0] 完全一样,内积是 1;两个向量 [1, 0] 和 [0, 1] 完全正交,内积是 0。

$$
\text{score}(i, j) = q_i \cdot k_j^\top
$$

把所有 Token 两两都算一遍,就是矩阵乘法 **Q × K^T**。

**为什么 K 要转置?**

Q 和 K 都是 n × d 的矩阵(n 个 Token,每个 d 维),形状一样没法直接相乘。把 K 转置成 d × n,Q × K^T 的结果就是 **n × n 的分数矩阵**,每一格刚好对应一对 Token 的相似度。

<!-- drawio 源文件: ./drawio/qkv_cal_01_qk_transpose.drawio -->

![Q×K转置矩阵乘法](https://file1.kamacoder.com/i/web/20261022110413.png?v=20261005)

在我们的例子里,Q 是 3×2,K^T 是 2×3,结果是 **3×3 的分数矩阵**,每一格表示"**行 Token 对列 Token 的关注程度**"。

手算一下:

|   | 我 | 爱 | 你 |
|---|----|----|-----|
| **我** | 1  | 0  | 1  |
| **爱** | 0  | 1  | 1  |
| **你** | 1  | 1  | **2**  |

第一行第一列是 1,代表"我"对"我"的相似度是 1。第三行第三列是 **2**,代表"你"对自己的相似度最高——很合理,一个 Token 和自己当然最像。

**维度检查很重要**:Q(n × d_k) 乘以 K^T(d_k × n),结果是 (n × n)。面试时能说清楚维度变化,说明你真的理解了矩阵运算的含义。

## 第二步:缩放(为什么要除以√d_k?)

上一步得到的分数,可能会非常大——尤其是当向量维度 d_k 很高的时候。

来看个例子,假设两个 64 维的向量,每个分量都是随机数,它们的内积期望值大概是 **64 倍**于 1 维的情况。分数越大,Softmax 之后的分布就越"尖锐":最大的那个接近 1,其他的接近 0。

这会导致什么?**Softmax 进入饱和区,梯度接近 0,模型根本学不动。**

解决方式很简单——除以 √d_k:

$$
\text{scaled score} = \frac{QK^\top}{\sqrt{d_k}}
$$

**为什么是除以√d_k,而不是 d_k?**

假设 Q 和 K 的每个分量都是均值为 0、方差为 1 的随机变量,那么它们的内积(d_k 个分量相乘再相加)的方差就是 d_k。除以 √d_k 之后,方差变回 1,分数的分布就稳定了。

我们的例子里 d_k = 2,√2 ≈ 1.41,缩放后:

|   | 我 | 爱 | 你 |
|---|----|----|-----|
| **我** | 0.71  | 0  | 0.71  |
| **爱** | 0  | 0.71  | 0.71  |
| **你** | 0.71  | 0.71  | **1.41**  |

分数被"压平"了一些,Softmax 就不会那么极端。

## 第三步:Softmax(把分数变成权重)

现在的分数还是普通数字,有正有负,我们需要把它们变成**概率**——非负,且每行加起来等于 1。

这正是 Softmax 做的事:

$$
\text{softmax}(z_i) = \frac{e^{z_i}}{\sum_j e^{z_j}}
$$

**对每一行单独做 Softmax**,以"我"这一行为例:

分数:[0.71, 0, 0.71]

$$
e^{0.71} \approx 2.03, \quad e^0 = 1.00, \quad e^{0.71} \approx 2.03
$$

总和 = 5.06,归一化后:

$$
[2.03/5.06,\ 1.00/5.06,\ 2.03/5.06] \approx [0.40,\ 0.20,\ 0.40]
$$

三行全部算完,得到**注意力权重矩阵 A**:

|   | 我 | 爱 | 你 |
|---|----|----|-----|
| **我** | 0.40  | 0.20  | 0.40  |
| **爱** | 0.20  | 0.40  | 0.40  |
| **你** | 0.25  | 0.25  | **0.50**  |

可以验证,每行加起来都等于 1 ✅

"你"关注自己的权重是 0.50,是关注另外两个词(各 0.25)的 2 倍。这说明 Attention 自动判断出:在当前这句话里,"你"最应该关注自己携带的信息。

![Softmax归一化权重](https://file1.kamacoder.com/i/web/20261022110415.png?v=20261005)

## 第四步:加权求和(用权重"取"出信息)

最后一步,用注意力权重矩阵 A 对 V 做加权求和:

$$
\text{Output} = A \cdot V
$$

A 是 3×3,V 是 3×2,输出是 **3×2**,和输入 X 同形。

以"你"为例,它的权重行是 [0.25, 0.25, 0.50],V 矩阵的三行分别是:

- v₁(我)= [1, 0]
- v₂(爱)= [0, 1]
- v₃(你)= [1, 1]

$$
\text{out}_\text{你} = 0.25 \times [1,0] + 0.25 \times [0,1] + 0.50 \times [1,1] = [0.75,\ 0.75]
$$

"你"的输出向量 [0.75, 0.75] 是三个 Token 信息的**加权混合**,但对自身的权重更大。

这就是 Attention 的本质:**每个 Token 的输出,都是全局信息的一次加权聚合,权重由相似度决定。**

## 串起整个流程

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

| 步骤 | 操作 | 输入 | 输出 | 目的 |
|------|------|------|------|------|
| ① | Q × K^T | Q(n×d), K(n×d) | 分数矩阵(n×n) | 计算每对 Token 的相似度 |
| ② | ÷ √d_k | 分数矩阵(n×n) | 缩放后的分数(n×n) | 防止分数过大导致梯度消失 |
| ③ | Softmax(按行) | 缩放后的分数(n×n) | 权重矩阵(n×n) | 把分数变成概率权重,行和为 1 |
| ④ | × V | 权重矩阵(n×n), V(n×d) | 输出(n×d) | 按权重加权求和,聚合上下文信息 |

**输入是 n×d,输出还是 n×d,维度不变,但每个 Token 的向量里已经融合了全局的上下文信息。**

## 面试怎么回答

面试官问"Attention 是怎么计算的",你可以这样答:

**第一层:四个步骤**

"Attention 分四步:QK^T 算相似度、除以根号 d 缩放、Softmax 归一化、乘以 V 加权求和。最终每个 Token 的输出都是所有 Token 信息的加权平均。"

**第二层:为什么这么设计**

"K 转置是为了让 Q 和 K 相乘得到 n×n 的分数矩阵,每一格对应一对 Token。除以根号 d 是为了防止维度高时分数过大,导致 Softmax 饱和、梯度消失。Softmax 把分数变成概率,保证每行和为 1,这样每个 Token 都按权重聚合全局信息。"

**第三层:工程影响**

"如果不缩放,d_k 很大时 Softmax 会进入饱和区,几乎所有梯度都集中在最大值那个位置,其他位置学不到东西。实际项目里如果 Attention 权重分布太尖锐,往往就是缩放没做好。"

**能说到第三层,面试官会觉得你不是死记硬背,是真的理解了 Attention 的设计权衡。**

## 知识拓展

### 1. Attention 权重矩阵是对称的吗?

不一定。在我们的例子里,Q = K,所以 QK^T 是对称矩阵。但真实训练中 Q 和 K 是由不同的权重矩阵 W_Q 和 W_K 生成的,QK^T 就不对称了。

不对称很合理:"我"关注"你"的权重,和"你"关注"我"的权重,为什么要一样?

### 2. 为什么不用其他相似度度量,比如余弦相似度?

点积计算简单,矩阵乘法可以高度并行,GPU 优化得很好。余弦相似度需要额外计算向量的模长,多一步归一化,效率低,实践中没必要。

### 3. Softmax 之前的分数矩阵能直接拿来用吗?

不能。分数没有归一化,不同位置的"重要程度"没有可比性。加权求和时权重和不为 1,输出的量纲也不对。Softmax 保证了权重是概率分布,加权平均才有意义。

### 4. 如果序列很长,n×n 的权重矩阵会不会太大?

会。这是 Transformer 的主要瓶颈之一。序列长度 n = 8192 时,权重矩阵是 8192×8192 ≈ 6700 万个浮点数,显存占用巨大。后续很多优化(稀疏 Attention、线性 Attention)都在尝试降低这个二次复杂度。

### 5. 缩放系数一定是√d_k 吗?能不能换成其他值?

可以,但√d_k 有理论依据:假设 Q 和 K 的分量是均值 0、方差 1 的独立随机变量,内积的方差就是 d_k,除以√d_k 后方差变回 1。实际项目里如果 Attention 权重分布不稳定,可以试试调整缩放系数,但大部分情况√d_k 够用。

## 本文小结

Attention 的计算过程看起来复杂,本质是四个步骤:算相似度、缩放、归一化、加权求和。

**面试官追问的都是工程直觉**:为什么 K 要转置?为什么要除以√d_k?这些问题的答案不在公式里,在计算过程里——转置是为了得到 n×n 的分数矩阵,缩放是为了防止梯度消失。
